## 📌 Активный бэклог задач

### 1. Задача CVH-044: Интерактивное создание ролей и стадий через `cvh-dev`

#### Концепция
Не раздувать фронтенд сложными формами и модалками на 2000 строк кода. Настройка ролей, колонок и политик инструментов — прямая обязанность мета-агента `cvh-dev`.

#### План реализации
1. **UI Триггер**:
   - На доске в контекстном меню или рядом с кнопкой добавления колонки сделать действие: *«Настроить роль через AI (cvh-dev)»*.
   - Открывает быстрый диалог / промпт: например, *«Добавь стадию 'Дизайн' с агентом-верстальщиком на Tailwind»*.
2. **Автоматизация через `cvh-dev`**:
   - Агент `cvh-dev` атомарно:
     1. Создаёт папку `.cvh/agents/<role>/` (`persona.md`, `setting`).
     2. Регистрирует колонку в `.cvh/boards.json` (SSOT).
     3. Настраивает разрешения инструментов в `.cvh/settings/tool-policy.json`.
     4. Перезагружает конфигурацию досок через IPC.

### 2. Задача CVH-045: Вынос базы данных на личную VPS (Синхронизация Дома и Работы без костылей и JSON)

#### Мотивация: отказ от «JSON-костылей» и изоляция данных
- Плодить текстовые `.json` файлы для синхронизации в git-репозитории — костыльно, раздувает коммиты и небезопасно.
- Хранить сам бинарный `harness.db` в Git нельзя из-за неразрешимых мерж-конфликтов.
- **Идеальное архитектурное решение**: Использовать личную VPS как центральный защищённый хаб данных (Single Source of Truth для задач и диалогов), оставив в локальном Git только чистый исходный код и конфиги досок.

#### Рекомендуемый вариант реализации: `sqld` (LibSQL Server в Docker) ⭐
- **Что это**: Открытый форк SQLite от авторов Turso, написанный на Rust. Поддерживает протокол SQLite по HTTP/WebSockets и встроенную двустороннюю репликацию.
- **Интеграция в Tauri (`src-tauri`)**:
  - В `Cargo.toml` подключается крейт `libsql = { version = "0.6", features = ["replication"] }`.
  - Режим **Embedded Replica**: приложение читает и пишет в локальный файл кэша на диске (скорость остаётся нативной микросекундной, UI не лагает при плохом интернете), а движок в фоне асинхронно синхронизирует транзакции с `http://vps-ip:8080` по токену.
  - Если на ноутбуке нет интернета — работа офлайн. Появился интернет — все изменения автоматически улетели на VPS и подтянулись на втором ПК.
- **Настройки в UI (`SettingsModal.tsx`)**:
  - Переключатель: `Включить VPS-синхронизацию`
  - Поле: `VPS Endpoint` (например, `https://vps.yourdomain.com:8080`)
  - Поле: `Auth Token` (хранится в заигноренном файле `.cvh/llm.json` или системном хранилище ключей).

### 3. Задача: Поддержка отрицательного offset (`tail`) в `read_file`

#### Проблема
При чтении логов или больших файлов агенты вынуждены последовательно скроллить к концу файла, расходуя контекст.

#### План реализации
- В `src-tauri/src/agent/tools/file_ops.rs` поддержать отрицательный `offset`:
  - При `offset < 0` (например, `offset: -50`) отдавать последние 50 строк файла с честными абсолютными номерами строк.
  - Покрыть юнит-тестами в `tools_fs_tests.rs`.

### 4. Задача: Улучшение декодирования OEM/CP866 на Windows в `execute_command`

#### Проблема
Когда системные утилиты `cmd.exe` или сторонние компиляторы на русскоязычной Windows возвращают ошибки в системной кодировке CP866/Windows-1251, `String::from_utf8_lossy` возвращает кракозябры.

#### План реализации
- В `run_scoped_command` (`src-tauri/src/agent/tools/command.rs` / `agent.rs`):
  - При ошибке валидации UTF-8 пробовать декодировать через `encoding_rs::IBM866` или `WINDOWS_1251`.
  - Обогатить окружение стандартными путями Node/pnpm/Cargo (`%LOCALAPPDATA%\pnpm`, `%APPDATA%\npm`, `%USERPROFILE%\.cargo\bin`).
